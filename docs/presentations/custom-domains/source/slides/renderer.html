Building the page

The renderer: from a name to a page

1 · nginx

Hands it over

The request reaches the renderer (port 3001) with the website's name attached, in the Host header.

2 · API

Which website?

The API matches the name to a verified custom domain, or to a platform address (leela-garden is the site's slug).

3 · Postgres

What's published?

The API reads the last published version: pages, theme, text, images. Drafts never leak.

4 · Renderer

Draw and remember

It builds the HTML and keeps a cached copy, so the next visitor gets it instantly. Publishing clears the cache.

About your setup today

nginx tells the renderer “this is leela-garden.sites.surajthapa247.com.np” instead of passing leelagarden.com.np through. Both lead to the same website. Passing the real name through later would let Atrium apply its own primary-domain and redirect rules.

The renderer is a Next.js app that can draw any Atrium website; the name in the request decides which one. It asks the API at /v1/public/sites/resolve?host=... and gets back a snapshot of the last published version. It caches the result, so a busy site barely touches the database. When you click Publish, Atrium tells the renderer to forget its copy, and the next visitor sees the new version.
